## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon/authenticated client → Postgres (RLS) | Public read clients query member_publications; RLS governs what they can see. No write path is exposed to anon/authenticated. |
| service_role (trigger execution context) → tables | The sync trigger fires under the role that wrote to `members` (service_role via createSupabaseAdminClient), which has BYPASSRLS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Information Disclosure / Tampering | member_publications table without RLS | mitigate | `ALTER TABLE member_publications ENABLE ROW LEVEL SECURITY;` + a single `FOR SELECT USING (true)` policy — no anon/authenticated INSERT/UPDATE/DELETE policy exists, so writes are denied to public roles (Task 1 Statement 3, Task 2). Matches the other four tables exactly. |
| T-25-02 | Denial of Service | sync trigger writes blocked by new RLS policy | accept | service_role has BYPASSRLS (schema.sql L66-68); triggered writes are unaffected. No SECURITY DEFINER needed — the function runs in the writer's (service_role) context, which already bypasses RLS. Verified, low risk. |
| T-25-03 | Tampering | SQL injection via trigger function | accept | The trigger function uses only static SQL (NEW.*/OLD.* column refs, no dynamic SQL string concatenation, no EXECUTE). No injection surface (RESEARCH Security Domain). |
| T-25-04 | Elevation of Privilege | trigger function privilege escalation via SECURITY DEFINER | mitigate | The function is NOT declared SECURITY DEFINER (default SECURITY INVOKER) — it runs with the caller's privileges (service_role), so it grants no escalation. Plan explicitly omits SECURITY DEFINER. |
| T-25-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — SQL-only schema migration (RESEARCH Package Legitimacy Audit: N/A). No slopcheck checkpoint required. |
