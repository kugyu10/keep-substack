## Component Inventory

This phase adds or modifies the following UI elements. No new components are created; all changes are extensions of existing components.

### MyProfileForm.tsx — @handle input field (new, PROF-01)

```
<div>
  <label htmlFor="substack_handle" className="block text-sm font-semibold mb-1">
    Substack ハンドル
  </label>
  <input
    id="substack_handle"
    name="substack_handle"
    type="text"
    placeholder="@yourhandle"
    defaultValue={substackHandleDefault}
    className="w-full border rounded px-3 py-2 text-sm"
  />
  <p className="text-xs text-gray-500 mt-1">
    例: @yourname — 入力すると個人ページからプロフィールへのリンクが作成されます
  </p>
</div>
```

Placement: immediately below the `name` field, above the 所属チーム field.
Input behavior: accepts `hoge` or `@hoge`; normalization is server-side only (D-07, D-08).
Pre-fill: `defaultValue` is `member.substack_handle ?? searchParams.handle ?? undefined` (D-06).

### CalendarGrid.tsx — conditional profile link (new, PROF-02)

The avatar+name header block (lines 44-57) gains a conditional `<a>` wrapper when `substackHandle` prop is present.

```
{substackHandle ? (
  <a
    href={`https://substack.com/${substackHandle}`}
    target="_blank"
    rel="noopener noreferrer"
    className="block hover:opacity-80"
  >
    {avatarNameBlock}
  </a>
) : (
  avatarNameBlock
)}
```

Visual affordance: `hover:opacity-80` only — no underline, no color change. The avatar+name block is already visually distinct; adding pointer cursor (`cursor-pointer` via `<a>`) is sufficient.
No new icon or indicator is added to signal the link — the href is the only signal.

## Interaction Contract

### /my page — @handle input (PROF-01)

| State | Visual |
|-------|--------|
| Empty (handle not set) | Placeholder text `@yourhandle` visible; input border `border-gray-300` (Tailwind default) |
| Pre-filled from searchParams | `defaultValue` set to `?handle=` param value; input shows the param value |
| Pre-filled from DB | `defaultValue` set to stored `@handle` value (takes precedence over searchParams) |
| Pending (form submitting) | Submit button shows `保存中...` + `disabled:opacity-50`; same as existing form pending state |
| Success | Page revalidates (`revalidatePath('/my')`); form re-renders with saved value in input |
| Error (server action returns string) | `<p role="alert" className="text-sm text-red-600">` displays above form — same as existing error pattern |

No client-side validation state. No inline field-level error. Validation is server-side only (D-07).

### /member/[publicationId] — profile link (PROF-02)

| State | Visual |
|-------|--------|
| substackHandle present | Avatar+name block is wrapped in `<a>`; cursor changes to pointer on hover; opacity drops to 0.8 on hover |
| substackHandle absent (null or undefined) | Avatar+name block renders as static `<div>` — identical to current behavior |

Click behavior: opens `https://substack.com/@handle` in a new tab (`target="_blank"`).
No visual badge, icon, or "external link" indicator is added.

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Label association | `<label htmlFor="substack_handle">` + `<input id="substack_handle">` explicit pairing |
| Error announcement | `role="alert"` on error `<p>` — existing pattern; screen readers announce on render |
| External link | `<a target="_blank" rel="noopener noreferrer">` — browser announces "(opens in new tab)" for assistive tech |
| Touch target | @handle input: `px-3 py-2` = 40px height — acceptable for text input (44px required for interactive controls, not text inputs per WCAG 2.5.5) |
| Disabled state | Submit button: `disabled` + `aria-disabled={isPending}` — existing pattern |
