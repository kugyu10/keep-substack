## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label padding |
| sm | 8px | Compact element spacing (button padding-y, note margin) |
| md | 16px | Default element spacing (px-4, horizontal page gutter) |
| lg | 24px | Section padding (mb-6, form field gap) |
| xl | 32px | Layout vertical whitespace (py-8 blocks) |
| 2xl | 48px | Auth page top/bottom padding (py-12 within (auth) layout) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Auth page `<main>` currently uses `py-16` (64px). After Route Group migration it becomes `py-12` (48px) because the auth layout supplies its own outer padding — the combined effective spacing for login form from top of viewport remains approximately 64–72px total. Use `py-12` in each login page `<main>` after layout wraps it.
- Header nav button touch target: `px-3 py-1` (12px × 4px) — existing pattern, no change this phase.

Source: existing code patterns; confirmed against 8-point scale

## UI-03: Footer Copy Contract

Footer is a Server Component. Three exclusive states:

| State | Condition | Rendered copy |
|-------|-----------|---------------|
| Unauthenticated | `user === null` | `このSubstack継続可視化ツールに参加したい方は` + link text `コチラ` → `https://uojun.substack.com/p/8cd` |
| Authenticated + member linked | `user !== null && publicationId !== null` | `あなたの個人ビューは` + link text `コチラ` → `/member/{publicationId}` |
| Authenticated + member unlinked | `user !== null && publicationId === null` | `参加登録は` + link text `コチラ` → `/my` |

Layout: `<footer className="py-4 text-center">` (identical to current)
Text wrapper: `<span className="text-xs text-gray-400">`
Link style: `hover:text-[#FF6719] underline`
Internal links: use `<Link>` (next/link). External link (unauthenticated): `<a target="_blank" rel="noopener noreferrer">`.

Source: CONTEXT.md D-10, D-11, D-12; existing `src/app/layout.tsx` footer

## UI-04: Sort Order Contract

### Member grouping (D-14, D-15)

Group priority (A before B before C):

| Group | Condition | Position |
|-------|-----------|----------|
| A | `hasUser === true && slots.length > 0` | Top — commit-configured |
| B | `hasUser === true && slots.length === 0` | Middle — logged-in but no commit |
| C | `hasUser === false` | Bottom — unregistered |

### Sort keys within each group (D-13, D-17, D-18)

Priority order descending / ascending as noted:

1. This week's achievement rate — `achievementRate(slots, getWeekDates(0), dateMap)` — descending
2. Streak weeks — `consecutiveWeekStreak(slots, items)` — descending (unchanged)
3. Last week's achievement rate — `achievementRate(slots, getWeekDates(-1), dateMap)` — descending
4. Two-weeks-ago achievement rate — `achievementRate(slots, getWeekDates(-2), dateMap)` — descending
5. `addedAt` — ascending (earlier registered first)

`achievementRate` must be refactored to accept `(slots, weekDates, dateMap)` signature and exported or called internally with pre-built date maps per week offset.

No visible UI change for the sort — the reorder is purely data-layer. No labels or indicators added to CommitGoalView in this phase.

Source: CONTEXT.md D-13 through D-18

## UI-05: HeaderNav Contract

### `HeaderNav.tsx` (Client Component)

Props interface:
```ts
type HeaderNavProps = {
  user: User | null  // from supabase.auth.getUser()
}
```

Behaviour:
- `usePathname()` to read current path
- If `user !== null && pathname !== '/my'`: render `<Link href="/my">マイページ</Link>` button
- If `user !== null && pathname === '/my'`: render nothing (button hidden)
- If `user === null`: render `<Link href="/login">ログイン</Link>` button

Button style (both variants, unchanged from current Header): `text-sm border border-gray-300 rounded px-3 py-1 hover:bg-gray-50 transition-colors`

`Header.tsx` stays Server Component: fetches `user`, renders logo link + `<HeaderNav user={user} />`.

Source: CONTEXT.md D-19, D-20, D-21; `src/components/Header.tsx`
