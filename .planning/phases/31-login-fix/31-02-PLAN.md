<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → sendMagicLinkAction | フォームの hidden input から pid/handle が渡される。不完全なリンクからのアクセスは早期エラー |
| Magic Link → auth/callback | Supabase が発行した OTP コード。code exchange 成功後のみ member 操作を実行 |
| auth/callback → members テーブル | admin client (BYPASSRLS) で member を INSERT する。user_id を同時に設定するため、作成直後から他ユーザーによる同 pid 紐付けは不可 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-03 | Spoofing | auth/callback member INSERT | mitigate | INSERT 時に `user_id: user.id` を同時設定。作成直後から正しいオーナーに紐付く |
| T-31-04 | Tampering | sendMagicLinkAction pid/handle | mitigate | D-01: `!pid \|\| !handle` で早期リターン。不完全リンクから Magic Link を送信不可にする |
| T-31-05 | Tampering | substack_handle squatting | mitigate | DB UNIQUE 制約（Plan 01 で適用済み）+ 23505 フォールバック INSERT（substack_handle=null）で既存 handle の横取りを防止 |
| T-31-06 | Elevation of Privilege | updateMyProfileAction | mitigate | `.eq('user_id', user.id)` で自分の member 行のみ UPDATE。他ユーザーの handle を変更不可 |
| T-31-07 | Information Disclosure | 23505 エラーメッセージ | accept | 「このハンドルはすでに使用されています」は handle 使用中という情報を開示するが、handle は公開情報（Substack プロフィール URL で誰でも確認可能）のため許容 |
| T-31-SC | Tampering | npm/pip/cargo installs | accept | 新規パッケージインストールなし。既存スタックのみ使用 |
</threat_model>
